# Tests

Each suite opens the built `index.html` in headless Chromium, mostly as a Samsung Galaxy S20 Ultra (412 × 915), and prints one `PASS` or `FAIL` line per check. `node tests/run.js` runs them all and exits with 1 if anything failed, a page threw an error, or a suite didn't finish (or ran past fifteen minutes).

The suites run side by side, as many at a time as there are processor cores (at most four; `--jobs N` to choose), longest first, each in its own process with its own browser. Each suite's results print in one piece as it finishes. The publishing workflow runs them the same way before the site goes up, and keeps the screenshots of a failed run for a week.

## Helpers

- `pw.js` loads Playwright. It tries `$PLAYWRIGHT`, then `playwright`, then `/opt/npm-tools/node_modules/playwright`. It also gives the suites the app's location and `tests/out/` for screenshots.
- `wake-mock.js` stands in for the Screen Wake Lock API on every page (headless Chromium refuses the real one). `window.__wl` counts requests and releases; localStorage `test.wl` set to `deny` or `none` makes requests fail or hides the API.
- `mic-mock.js` is a stand-in microphone, injected with `page.addInitScript(micMock, { bpm, label, devices, fail })`: getUserMedia returns a real audio stream of breath-like noise, louder on each out-breath, at the pace given (or `window.__micBpm` if a test sets it first), with the microphones to choose from, or an error; `window.__mic` counts calls and stopped tracks.
- `sensor-mock.js` is a stand-in Bluetooth heart-rate sensor, injected with `page.addInitScript(mock, { speed, rr, fail })`. Its `speed` option runs the page's clock faster, so a 30-minute nap takes a minute. Heart rate swings with each breath around 64 bpm: `window.__hrBase` moves the middle, `window.__hrAmp` sets the swing and `window.__rrJitter` shakes each interval, like a loose clip.
- Setting localStorage `entrain.debug` to `1` exposes the app's state as `window.__entrain` for the checks.
- `unlock-helper.js` is for every suite that uses the new techniques, which open with a donation. `testApp()` writes `tests/out/entrain-unlock.html`, the built page with its `SUP_KEYS` line replaced by the public half of a TEST-ONLY key, and returns its file URL. The key is made the first time a suite needs it and kept as `tests/out/unlock-test-key.pem`, outside git, so no private key is in the repository and the real build never trusts it; suites running side by side share it; `unlockInit(page)`, before `goto`, stores device `TEST0TEST0` and a code the test key signed for it, so the copy opens unlocked; `unlocked(page)` waits until that code has been checked. `sign(device)` makes a code for any device.
- Headless Chromium sometimes loses a `file://` page's storage across a reload. Checks that reload copy the stored values over (`reopen()` in `regress.js`, the builder in `prrun2.js`) and print a `NOTE` line when they had to.
